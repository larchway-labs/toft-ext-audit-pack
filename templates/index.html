Running it

Unpack it, point it at this install, and sign in as an administrator when it asks. It writes a directory containing report.html — one self-contained page, no network needed to read it — alongside the raw JSON and the screenshots, and a manifest with a SHA-256 of every file.

tar xzf toftaudit_{{ detected or 'linux_amd64' }}.tar.gz
./toftaudit --url {{ install_url or 'https://toft.example.com' }} --out ./audit-2026-09-01

# It prompts for the administrator username and password. To run it
# unattended, supply them in the environment instead:
LPAUDIT_USER=admin LPAUDIT_PASSWORD=... ./toftaudit --url ... --out ...

# Screenshots need a Chrome or Chromium on your machine. Without one it
# collects everything else and says which items it could not picture:
./toftaudit --url ... --out ... --no-screenshots

The credential is never a flag — it is prompted for or taken from the environment, which is the same rule Toft's own toft client follows. Nothing is written back to the install: toftaudit issues reads only, and sends X-Toft-Scan: 1 so its traffic is not counted as somebody using your apps.

The organization-defined parameters

800-171 asks the organization to define {{ coverage.odp_total }} parameters — a period here, a frequency there. {{ coverage.odp_bound }} of them are values a Toft install already holds, and this pack binds them to the live setting rather than asking you to write the number down twice: the account-inactivity period is dormant_lock_days, the session-termination period is session_idle_minutes, the malware response is dependency_block_malware.

{{ coverage.odp_noted }} more are noted as organizational with no Toft setting behind them, and {{ coverage.odp_unaddressed }} are not addressed by this pack at all. That last number is shown because a coverage figure you cannot see is a coverage figure you cannot trust.
